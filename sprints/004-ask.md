# 004 — Ask: provider interface, `claude -p` adapter, ask-model setting

## Goal

korg proposal 3368. It covers two work items:

- korg 3360: the AI pane goes live for ask. This means a Provider interface,
  a first adapter running headless `claude -p` on kai, and answers grounded in
  the frame and shown transiently. "Keep this" stores an answer in a format
  grow (3364) will consume. It also brings the app config file and the
  ask-model setting.
- korg 3366: scope the S/T single-key shortcuts for WCAG 2.1.4, now that the
  AI pane has a real text box.

## Decisions

- **Premises held.** There was no AI backend: the pane's Send only printed
  "not connected". S and T fired anywhere but a text field, so they fired on
  Send, the gear and the bare page. `claude` 2.1.283 is on kai. kloom is not
  in the cross-project plan index.
- **The sanitiser comments on 3360 are grow's.** Two comments on 3360 carry
  the sprint-001 review's precondition, a real SVG sanitiser before the
  model writes illustrations. It belongs to grow, which is where proposal
  3369 carries it (3365). Ask writes no SVG, and answers render with images
  turned off.
- **The Provider interface** (`engine/ai/provider.ts`). `ask()` returns an
  async iterable of text chunks, and an error is one final event. The request
  carries an `AskContext` (subject title, frame, trail), the question, a
  server-checked model id and an `AbortSignal`. The prompt is shared by every
  adapter, so a Claude API adapter is one more class. The full account is in
  docs/design.md §Ask.
- **How `claude -p` is invoked.** This was settled by running it:
  - argv only, with no shell;
  - an empty working directory under `$TMPDIR`;
  - `--tools ""`, `--strict-mcp-config`, `--setting-sources ""`,
    `--disable-slash-commands` and `--no-session-persistence`;
  - kloom's own system prompt, with the prompt on stdin;
  - a 120s timeout.

  `--bare` was rejected because it takes only `ANTHROPIC_API_KEY`, not the
  subscription. The probe's init line confirmed `tools: []` and
  `mcp_servers: []`, and the model said it had no homelab instructions.

- **Streaming via stream-json works cleanly.** With
  `--include-partial-messages`, `text_delta` lines arrive, and the adapter
  yields each one. An unknown model comes back as a `result` with
  `is_error: true` ("There's an issue with the selected model"), which the
  adapter reports. No polling was needed.
- **Concurrency: one turn, three waiting.** Each waiter gets a `queued`
  event. A fifth request is refused with 503. An aborted waiter leaves the
  queue.
- **Moving the spine during a turn** does not stop it. The answer keeps the
  frame it was asked about, and its heading says which. A new question
  cancels the running one.
- **Which frame: the reading pane's.** In manual sync the narrative can
  show another frame than the spine, and "Ask about what you are reading"
  means the narrative. I found this in the browser pass: the first version
  asked about the spine's frame.
- **The kept-answer format** (`engine/ai/kept.ts`) is
  `kloom.kept-answer` version 1. It carries the anchor, the question, the
  answer markdown, and the frame's citations and sources that the answer's
  `[n]` markers named, in the §Citations shape (the design asked ask's keep
  to carry "the ones its answer used"). It also has the provider, the model
  and the timestamps. `keptAnswerProblems` validates a file for grow.
- **Keep sends an id, not text.** The server remembers finished answers (50
  of them, for an hour) and writes only what it remembers, so the client
  cannot forge a kept answer. Files go to `data/<subject>/kept/`
  (`$KLOOM_DATA_DIR`), git-ignored. That is outside `subjects/`, because a
  kept answer is a candidate, not content.
- **The app config** is `kloom.config.json`, committed and read per request.
  It lists the models (display name and id), names the provider, and gives
  ask's default (Sonnet 5). Validation refuses an id that could read as a
  flag. `resolveModel` honours only a listed id.
- **The ask-model row.** `modelSetting()` builds a `Setting` from the
  choices the page load serves, and it becomes the second select in the
  gear's panel. No other settings code changed, as the 003 registry
  intended.
- **Key scoping (3366).** Key routing moved out of `Shell.svelte` into a
  pure `pageKey(key, target)` (`engine/keys.ts`), so it is unit-testable in
  the node test environment. S and T need the focus to be in `.spine` or
  `.narrative`. Arrows, Home/End and Esc are unchanged. The hint bar now
  reads "S sync and T trail, in the spine or narrative".

## Verification

- `just check` passes: svelte-check shows 0 warnings, prettier and eslint
  are clean, and vitest runs 134 tests (96 before). The new tests cover:
  - page keys in every scope
  - the prompt and its reference numbering
  - the adapter against a fake `claude`: argv; streaming; the result
    fallback; an error result; exit without a result; the timeout; abort
  - the queue: order, the limit, an aborted waiter
  - the context builder against western-civ, including refusals
  - the NDJSON reader across chunk boundaries
  - the app config, including flag-shaped ids and pass-through attempts
  - ask turns: done, error, empty, queued, forgotten answers
  - keep: one valid file, idempotent
  - the page's Ask model drop-down and hint bar
  - markdown with images off
- **Negative-tested.** Making S page-wide again, and letting `resolveModel`
  pass any string through, each failed its test (2 failed, 132 passed).
  Both were restored.
- **Live against `claude -p` on kai** (dev server):
  - an ask on printing-press whose body named
    `--dangerously-skip-permissions` as the model ran on Sonnet 5 (8s);
  - a trail-frame ask on Haiku 4.5 worked;
  - keep wrote a kept-answer file carrying the three citations the answer
    marked;
  - an unknown answer id got 404, and a `__proto__` frame got 400.
- **Keyboard-only browser pass** (Playwright, headless Chromium):
  - Begin, then → to 09/16, then 11 Tabs to the Ask box.
  - Typing "st" in the box stays there. t and s on Send do nothing, and Esc
    from Send refocuses the spine. t on the spine enters the trail, and Esc
    leaves it. t with focus on the bare page does nothing.
  - Enter asks. The button becomes Stop and the status reads "Asking Sonnet
    5…".
  - Esc then → moved the spine mid-turn. The answer finished ("Answer
    ready.") still about "Knowledge went VIRAL.".
  - With the answer region focused, → does not move the spine. Tab reaches
    Keep this, and Enter keeps it ("Kept").
  - The model select is labelled "Ask model", set to claude-sonnet-5, and
    offers Sonnet 5, Opus 5.5 and Haiku 4.5. Stop stops a running turn.
  - At 390px there is no horizontal scroll.
- **Deploying as a service on kai was not needed** to exercise ask. The dev
  server on loopback runs `claude -p` as Ken, which is exactly the
  subscription path. It stays on the roadmap.

## Follow-ups

- The `[n]` markers show as plain text in the answer. Linking them to the
  frame's sources is a small UI nicety, left for when grow shows how kept
  answers are used.
- The answer heading's text is "Answer about" for screen readers and
  "About" on screen. That is deliberate, but review it with the rest of the
  AI pane once grow adds its own controls.
- **Web search for ask (korg 3376), decided and moved to grow (3369).**
  Ask is locked to the frame plus the model's training, which is too narrow
  for a subject like AI. Headless web access was measured working
  (`WebSearch,WebFetch`: 17s, 2 searches and 1 fetch). Ken decided on:
  - an app-config `ask.web` of `allow` (the default), `deny` or `offer`;
  - an "Include web" checkbox in the AI pane unless the config says `deny`;
  - landing it with grow.
- **Layouts for the AI pane (korg 3377).** From Ken's first use of ask:
  compare the bottom strip, three columns, a narrative/ask tab pair, and a
  right-hand split.
